# BUILD.md

## Toolchain version parity
- clang-22 → LLVM 22.1.8 (installed via apt.llvm.org)
- rustc 1.98.1 (stable) → LLVM 22.1.8

No `rust-toolchain.toml` is used — the Dockerfile installs rustup's `stable`
channel directly, which currently matches clang-22's LLVM version. Re-verify
parity any time either toolchain updates:

    clang-22 --version
    rustc --version --verbose

---

## Folder convention (as of this file)

    benchmarks/<c_cpp|rust>/<tool>/
        src/            unmodified vendored source
        ir/              <tool>_O0.ll and <tool>_O2.ll together, no subfolders
        SOURCE.md
        NOTES.md

Generated automatically by `scripts/generate_benchmarks.sh` — see below.

---

## C (GNU coreutils)

Build workspace (gitignored, lives inside repo under `.build/`):

    mkdir -p .build && cd .build
    git clone --recurse-submodules https://github.com/coreutils/coreutils.git
    cd coreutils
    ./bootstrap
    ./configure --disable-gcc-warnings
    make

Note: plain `./configure` may fail on `make` with
`-Werror=maybe-uninitialized` in copy-file-data.c (known gnulib/coreutils
git-checkout issue, unrelated to this project) -- `--disable-gcc-warnings`
avoids it.

IR is generated by compiling each tool's `.c` file directly with clang-22
at `-O0` and `-O2`, using the same gnulib include paths the real build
uses. See `scripts/generate_benchmarks.sh` for the automated version.

---

## Rust (uutils/coreutils)

Build workspace (gitignored):

    mkdir -p .build && cd .build
    git clone https://github.com/uutils/coreutils.git uutils-coreutils
    cd uutils-coreutils
    cargo build
    cargo build --release

IR per tool is generated via `cargo rustc -p uu_<tool> -- --emit=llvm-ir`
(debug, standing in for O0) and `cargo rustc -p uu_<tool> --release --
--emit=llvm-ir` (release, standing in for O2). Note: rustc's debug/release
profiles are not a literal match for clang's `-O0`/`-O2` flags -- they're
the closest equivalent on the Rust side, not an identical optimization
pipeline. Document this if it matters for your methodology.

---

## Automated generation

    ./scripts/generate_benchmarks.sh

Creates the folder structure for all 10 tools (both languages), compiles
IR, and copies everything into place. Safe to re-run -- it won't overwrite
an existing SOURCE.md/NOTES.md, only creates them if missing. See the
script header for the exact tool list and any per-tool caveats.

---

## Known build issues
- gnulib/coreutils git checkout requires `--disable-gcc-warnings` (see above).
- If `./bootstrap` fails on a missing tool, install it via apt and retry --
  see the Dockerfile's gnulib prerequisite block for the full list
  (autoconf, automake, autopoint, gettext, gperf, texinfo, bison, m4,
  pkg-config, libtool, rsync, perl).
